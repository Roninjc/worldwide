# worldwide-relay

Zero-knowledge sync relay for the Worldwide PWA. A Cloudflare Worker backed by a KV
namespace that stores **one opaque, client-side-encrypted blob per user id**.

The relay never sees a location: the payload is ciphertext (tweetnacl `secretbox`)
whose key is derived from a passphrase that only ever lives on the user's devices.
A single relay can therefore serve every user without compromising anyone's privacy.

## API

| Method | Path     | Body               | Result                         |
| ------ | -------- | ------------------ | ------------------------------ |
| `PUT`  | `/{id}`  | base64 ciphertext  | stores the blob (`200 ok`)     |
| `GET`  | `/{id}`  | –                  | returns the blob (`404` if none) |
| `GET`  | `/`      | –                  | health check                   |

- `{id}` is a 32–64 char hex token (128–256 bit random). It is a **capability**:
  knowing it is required to read or overwrite. It's generated by the PWA when you
  enable encrypted sync and copied into Scriptable.
- CORS is open (`*`) so the installed PWA can fetch from any origin.
- Max payload: 2 MB.

## Deploy

```sh
cd relay
npm install
npx wrangler login                       # once, authenticates with your Cloudflare account
npx wrangler kv namespace create BLOBS    # prints an id
# paste that id into wrangler.toml → [[kv_namespaces]] id = "..."
npm run deploy
```

`wrangler deploy` prints the public URL (e.g. `https://worldwide-relay.<you>.workers.dev`).
That URL goes into the PWA's encrypted-sync settings and into the Scriptable script.

## Local development

```sh
npm run dev     # wrangler dev, with a local KV
npm test        # handler round-trip test against a Map-backed KV stub (no Cloudflare needed)
```

## Notes

- Overwriting is allowed by whoever holds the `id`. Since the `id` is a 128-bit
  secret, guessing is infeasible; if it ever leaked, an attacker could overwrite the
  blob with garbage but still cannot read it, and the PWA simply fails to decrypt and
  falls back to local data.
- To rotate: generate a new `id` in the PWA and update Scriptable. The old blob is
  orphaned (delete it with `wrangler kv key delete --binding=BLOBS <old-id>` if desired).
